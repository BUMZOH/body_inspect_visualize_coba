# 比率グラフのアニメーション解説

## 1. 概要

`animate_ratio_bars()` は、昼勤・夜勤の2本の比率バーを約2.52秒かけて動かし、最後に正確な比率とスタッフ写真を表示して効果音を鳴らす関数です。

アニメーションは、**50%を起点に目標値へ減速しながら近づく動き**と、**時間とともに小さくなる揺れ**を組み合わせています。

```python
def animate_ratio_bars(step=0):
    total_steps = 36

    # アニメーション終了時処理
    if step >= total_steps:
        for i in range(2):
            animated_ratios[i] = ratio_targets[i]
            draw_ratio_bar(i, show_percentage=True)

        update_staff_photos(frm_day_group, result_photo_modes[0])
        update_staff_photos(frm_night_group, result_photo_modes[1])

        # 結果発表音
        winsound.PlaySound(
            str(BANG_SOUND),
            winsound.SND_FILENAME | winsound.SND_ASYNC,
        )
        return

    progress = step / total_steps
    ease = 1 - (1 - progress) ** 3
    wobble = math.sin(step * 0.65) * 0.30 * (1 - progress ** 3)

    for i in range(2):
        target = ratio_targets[i]

        animated_ratios[i] = (
            0.5 + (target - 0.5) * ease + wobble
        )

        animated_ratios[i] = max(
            0.02, min(0.98, animated_ratios[i])
        )

        draw_ratio_bar(i)

    root.after(70, animate_ratio_bars, step + 1)
```

## 2. 処理の流れ

1. `step=0` から開始する。
2. `step >= 36` なら最終表示・写真切替・効果音再生を行い終了する。
3. 途中なら `progress`、`ease`、`wobble` を計算する。
4. 昼勤・夜勤それぞれの `animated_ratios` を更新してバーを描画する。
5. `root.after()` で70ms後の次回実行を予約する。

`step` は0～35で途中描画を行い、36で終了処理に入ります。予約間隔の合計は `36 × 70 = 2520ms`（約2.52秒）ですが、実際には各回の処理時間などが加わります。

## 3. progress：進行度

```python
progress = step / total_steps
```

`progress` は0～1の進行度です。例えば `step=18` なら `18/36=0.5` で、時間的には半分です。

## 4. ease：終盤で減速する動き

```python
ease = 1 - (1 - progress) ** 3
```

これは **Ease Out Cubic（3次の減速補間）** です。開始直後に大きく進み、終了に近づくほど変化量が小さくなります。

| step | progress | ease |
|---:|---:|---:|
| 0 | 0.00 | 0.000 |
| 9 | 0.25 | 0.578 |
| 18 | 0.50 | 0.875 |
| 27 | 0.75 | 0.984 |
| 36 | 1.00 | 1.000 |

時間が半分の時点で、目標までの移動量の87.5%を進める計算です（揺れを除く）。

## 5. wobble：揺れの演出

```python
wobble = math.sin(step * 0.65) * 0.30 * (1 - progress ** 3)
```

| 部分 | 意味 |
|---|---|
| `math.sin(step * 0.65)` | 正負に振動する波。`0.65` は1ステップ当たりの位相変化（ラジアン） |
| `0.30` | 揺れの振幅を調整する係数 |
| `(1 - progress ** 3)` | 進行に伴って振幅を減らし、最後に0にする係数 |

`0.30` は比率の単位で30パーセントポイントに相当する係数です。ただし実際の揺れは `sin` と減衰係数により変化します。

## 6. animated_ratios：描画する割合

```python
for i in range(2):
    target = ratio_targets[i]
    animated_ratios[i] = (
        0.5 + (target - 0.5) * ease + wobble
    )
```

- `range(2)`：2本のバーを処理する。
- `0.5`：50%から開始する。
- `(target - 0.5) * ease`：50%から目標値へ移動する成分。
- `+ wobble`：揺れを上乗せする成分。

例えば目標値が80%（`target=0.8`）の場合、揺れを除くと以下のようになります。

| step | 計算 | 基本の比率 |
|---:|---|---:|
| 0 | `0.5 + 0.3 × 0` | 50.00% |
| 18 | `0.5 + 0.3 × 0.875` | 76.25% |
| 36 | `0.5 + 0.3 × 1` | 80.00% |

**注意：** この関数では2本のバーに同じ `wobble` を加えます。2本が常に合計100%になるとは限りません。終了時にはそれぞれの正確な `ratio_targets` に戻します。

## 7. max・min：描画範囲の制限

```python
animated_ratios[i] = max(
    0.02, min(0.98, animated_ratios[i])
)
```

途中の比率を2～98%に収めます。例えば計算値が1.10なら0.98、-0.10なら0.02です。終了時の目標値にはこの制限をかけません。

## 8. draw_ratio_bar：画面の更新

```python
draw_ratio_bar(i)
```

更新した比率を使ってバーを描画します。`draw_ratio_bar()` 自体の内部処理はここに提示されたコードには含まれません。

## 9. root.after：Tkinterのイベントループを利用

```python
root.after(70, animate_ratio_bars, step + 1)
```

70ms後に `animate_ratio_bars(step + 1)` を呼び出すよう、Tkinterに予約します。`time.sleep()` のようにGUIスレッドを停止して待つ方法ではありません。

`after()` は繰り返し処理を自動で行う命令ではなく、**次の1回を予約する命令**です。関数の末尾で毎回予約することでアニメーションが続きます。

## 10. 終了処理

```python
if step >= total_steps:
    for i in range(2):
        animated_ratios[i] = ratio_targets[i]
        draw_ratio_bar(i, show_percentage=True)

    update_staff_photos(frm_day_group, result_photo_modes[0])
    update_staff_photos(frm_night_group, result_photo_modes[1])

    winsound.PlaySound(
        str(BANG_SOUND),
        winsound.SND_FILENAME | winsound.SND_ASYNC,
    )
    return
```

1. `animated_ratios` を正確な目標値に置き換える。
2. `show_percentage=True` で最終の割合を表示する。
3. 昼勤・夜勤のスタッフ写真をそれぞれ切り替える。
4. `winsound.PlaySound()` で結果発表音を再生する。
5. `return` で終了し、次の `after()` は予約しない。

`SND_FILENAME` は音声ファイルを指定し、`SND_ASYNC` は再生終了を待たない指定です。

## 11. パラメータ調整の目安

| パラメータ | 大きくすると |
|---|---|
| `total_steps=36` | 同じ70ms間隔なら全体が長くなる |
| `after(70, ...)` | 描画間隔が長くなり、全体も遅くなる |
| `** 3`（ease） | 初期の進みが速く、終盤の減速が強くなる |
| `step * 0.65` | 揺れの周期が短くなる |
| `* 0.30` | 揺れ幅が大きくなる |

## 12. まとめ

この関数の構成は、**進行度 → 減速補間 → 揺れの追加 → 範囲制限 → 描画 → 次回予約**です。

Tkinterでは `root.after()` を使うと、GUIを止めずに少しずつ画面を更新できます。`ease` と `wobble` を独立して計算しているため、目標値への動きと演出の揺れを別々に調整できる点も重要です。
